The Little Paw Patissier

Sessions that finally stay put

By Yam Bartolome

For weeks the patisserie platform had a habit that made no sense: a customer would log in, the browser would hold the session cookie exactly as expected, and the very next request would come back as if nobody had ever signed in.

The culprit was not the login code. On shared hosting, PHP writes session files to a temporary directory that the host is free to clear, and clear it did — between one request and the next. The cookie survived. The file it pointed at did not.

Moving sessions into MySQL fixed it. A custom session handler stores each session as a row, which means the data lives exactly where the rest of the application's state already lives, and survives whatever the host does to its temp folders.

The lesson generalises past this one bug. Anything the application cannot afford to lose belongs in the database, not in a directory whose lifetime somebody else controls.

Game development

A board game learns to count its own gems

Gem Ko 'To! · in progress

Translating a physical board game into Unity turns out to be mostly a bookkeeping problem. The rules a group of players enforce by looking at the table have to become explicit state: whose turn it is, what is legal right now, and what happens when two effects resolve at once.

Current work is on the turn state machine, with the scoring pass written as a pure function so it can be tested without the board on screen.

Aislefront

Scoring a scene that hasn't been built yet

Audio production

Writing music for a game in progress means writing for a scene that keeps changing length. The answer has been to compose in loopable sections rather than fixed cues, so a passage can hold for eight bars or eighty without an audible seam.

Three sketches are tracked and waiting on the levels they belong to.
